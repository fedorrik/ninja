# Игры

Самостоятельный сайт для VPS: «Ночь ниндзя» (3–11 игроков) и «Секретный Гитлер» (5–10). Создание комнаты, вход по шестизначному коду или ссылке, общий стол и личные карты. Чата и аккаунтов нет. Все игровые действия проверяет сервер. Состояние хранится в SQLite.

## Запуск в одной Wi-Fi-сети

Сервер запускается на **одном компьютере**. На телефонах и остальных компьютерах нужен только браузер. Все устройства должны быть подключены к одной локальной сети; компьютер может быть подключён к тому же роутеру кабелем.

1. Распакуйте архив на компьютере. Нужен Python 3.11 или новее.
2. Windows: дважды нажмите **`start-lan.bat`**. Если появится запрос брандмауэра, разрешите Python доступ для **частной сети**.
3. Linux/macOS: откройте терминал в папке проекта и выполните **`sh start-lan.sh`**. Также можно выполнить `python3 start_lan.py` (Windows: `py start_lan.py`).
4. В окне появится адрес компьютера, например **`http://192.168.3.25:8080`**. Это только пример: используйте адрес, который выведет ваш сервер.
5. Откройте **этот же адрес на всех устройствах**, в том числе у хозяина комнаты. Создайте комнату и отправьте друзьям ссылку или код.

`192.168.3.1` — адрес вашего роутера. Открывать на нём игру или изменять его админку не нужно. Проброс портов для игры внутри домашней сети не требуется. `localhost` и `127.0.0.1` на телефоне указывают на сам телефон, поэтому используйте IP компьютера.

Окно сервера должно оставаться открытым, а компьютер — включённым и не в спящем режиме. Остановка — Ctrl+C. Комнаты сохраняются в `data/`. Не запускайте одновременно `server.py` и `start_lan.py` на одном порту. Если 8080 занят, используйте `python3 start_lan.py --port 8081` (Windows: `py start_lan.py --port 8081`).

Если адрес не открывается:

- Проверьте, что используется именно `http://`, верный IP и порт.
- Проверьте подключение к одной домашней сети; гостевая Wi-Fi-сеть или изоляция клиентов могут блокировать доступ между устройствами.
- Разрешите входящие подключения Python/TCP 8080 в брандмауэре компьютера для домашней сети. Отключать брандмауэр целиком не нужно.
- На Linux с активным UFW для вашей сети можно разрешить `sudo ufw allow from 192.168.3.0/24 to any port 8080 proto tcp`.
- Если сервер показал несколько адресов, выберите адрес домашнего Wi-Fi/Ethernet, а не VPN или виртуального адаптера.

Для сохранения входа пользуйтесь одним и тем же адресом. Переход с `localhost` на IP открывает другое хранилище браузера: лучше выбрать сетевой адрес до начала партии. Если роутер после переподключения выдаст компьютеру другой IP, сервер покажет новый адрес.

## Самый простой запуск на пустом VPS

Подходит Debian 12/13 или Ubuntu 24.04+, сервер с systemd, доступ по SSH и sudo. Ориентир для небольшой компании: 1 CPU, 1 GB RAM. Реальную нагрузочную ёмкость нужно измерять отдельно.

1. Загрузите архив на VPS через SFTP или `scp game-night.zip user@IP:~/`.
2. Подключитесь по SSH и распакуйте:

```bash
sudo apt-get update
sudo apt-get install -y unzip
unzip game-night.zip
cd game-night
```

3. Если домена нет:

```bash
sudo bash deploy/install.sh
```

Откройте `http://IP_СЕРВЕРА`. В панели VPS разрешите входящий TCP 80. Порт 8080 открывать наружу не нужно. Если включён UFW, разрешите `sudo ufw allow 80/tcp` и `sudo ufw allow 443/tcp`; перед любыми изменениями firewall сохраните доступ к вашему SSH-порту. Установщик сам firewall не меняет.

4. Если есть домен, создайте A-запись на IP VPS. AAAA добавляйте только при работающем IPv6. Вместо установки без домена выполните:

```bash
sudo bash deploy/install.sh games.example.ru
sudo certbot --nginx -d games.example.ru
```

Вместо `games.example.ru` подставьте свой домен. Разрешите TCP 80 и 443. Certbot запросит ваш email и настройку сертификата. После выпуска открывайте `https://games.example.ru`. Автопродление проверяется командой `sudo certbot renew --dry-run`.

Установщик рассчитан именно на пустой VPS: ставит Python, Nginx и Certbot из системного репозитория, создаёт пользователя `game-night`, сервис и виртуальный хост Nginx. Отключает стандартный виртуальный хост Nginx. Исходники помещаются в `/opt/game-night`, база — в `/var/lib/game-night`. При наличии установленного сервиса повторная установка прекращается.

После перезагрузки VPS сайт запускается автоматически.

## Проверка и обслуживание

```bash
sudo systemctl status game-night --no-pager
sudo journalctl -u game-night -n 100 --no-pager
sudo systemctl restart game-night
curl http://127.0.0.1:8080/health
```

Ответ `/health`: `{"ok": true}`. Если браузер не открывает сайт, проверьте firewall VPS, `sudo nginx -t` и адрес домена. Если порт 8080 занят, измените его и в unit-файле, и в конфигурации Nginx, затем выполните `sudo systemctl daemon-reload`, перезапустите сервис и перечитайте Nginx.

## Резервная копия

Самый понятный вариант — ненадолго остановить сервер и скопировать весь каталог базы:

```bash
sudo systemctl stop game-night
sudo tar -czf game-night-data-backup.tar.gz -C /var/lib game-night
sudo systemctl start game-night
```

Храните копию приватно: внутри есть скрытые роли и токены доступа игроков. Для восстановления остановите сервис, распакуйте каталог обратно в `/var/lib`, верните владельца `game-night:game-night` и запустите сервис. Не удаляйте базу при обновлении.

## Обновление

Распакуйте новую версию отдельно. Из её каталога:

```bash
sudo systemctl stop game-night
sudo cp -a server.py games static /opt/game-night/
sudo chown -R root:root /opt/game-night
sudo systemctl start game-night
```

Перед обновлением сделайте копию базы. Если меняется формат игрового состояния, безопаснее сначала закончить активные партии.

## Docker Compose — альтернативный способ

Если Docker Engine и Compose уже установлены:

```bash
docker compose up -d --build
```

Откройте `http://IP_СЕРВЕРА`. Для домена создайте в каталоге проекта файл `.env`:

```dotenv
SITE_ADDRESS=games.example.ru
```

Перезапустите `docker compose up -d`. Caddy автоматически запросит HTTPS-сертификат при корректном DNS и открытых TCP 80/443. Это отдельная альтернатива установщику: не запускайте оба способа одновременно на портах 80/443. Официальная установка Docker описана на https://docs.docker.com/engine/install/ .

```bash
docker compose logs --tail=100
docker compose restart app
docker compose down
```

Команда `down` сохраняет именованные тома. **Не используйте `down -v`**, если хотите сохранить комнаты. База находится в томе `game-data`, сертификаты — в `caddy-data`.

## Локально без Docker

Нужен Python 3.11 или новее. Сторонних пакетов нет.

```bash
python3 server.py
```

Откройте http://127.0.0.1:8080 . Чтобы пустить друзей из локальной сети: `HOST=0.0.0.0 python3 server.py`. На VPS используйте Nginx или Caddy перед сервером, как выше.

## Как пользоваться

Укажите имя, создайте комнату и отправьте ссылку друзьям. Они введут имена и присоединятся. Хозяин начинает игру, когда достигнуто минимальное число участников. Правила доступны из комнаты. Все надписи и карточки — на русском.

Секреты находятся в сворачиваемом личном блоке. При показе экрана держите его закрытым. На сервере каждый участник получает только разрешённые ему данные. Голоса и выбранные карты этапа открываются после решения всех живых игроков. Жетоны чести показываются владельцу, остальным видно только их количество.

Вход сохраняется **в том же браузере и на том же адресе**. Обновление страницы и перезапуск сервера не теряют место. Очистка данных браузера, режим инкогнито после закрытия, переход с HTTP на HTTPS или другой домен требуют нового входа; перед началом партии сразу выберите постоянный HTTPS-адрес. В текущую партию новые участники не добавляются. Один браузерный профиль рассчитан на одного игрока; для теста нескольких игроков используйте разные профили/браузеры.

Хозяин может передать управление. Если он не отвечает две минуты, другой участник может забрать управление. Выбывший из игры остаётся за столом. В «Ночи ниндзя» после утра хозяин запускает следующий раунд. В лобби можно выйти или удалить лишнего участника. Принудительного хода за отключившегося игрока нет: дождитесь его возвращения либо завершите партию кнопкой «Вернуться в лобби».

Комнаты хранятся 7 дней с последнего игрового изменения. Простое открытие страницы срок не продлевает. Один процесс сервера, один файл SQLite, без Redis и внешней БД. Опрос состояния примерно раз в 1,5 секунды. Проект предназначен для игры своей компанией; горизонтальное масштабирование несколькими процессами не предусмотрено.

## Структура и добавление игр

- `server.py` — комнаты, аутентификация токенами, HTTP, сохранение.
- `games/hitler.py`, `games/ninja.py` — независимые серверные правила.
- `static/app.js` — интерфейс и действия обеих игр.
- `static/style.css` — единый визуальный стиль.
- `static/rules.html` — русская памятка.
- `tests/` — сценарии и автоматические полные партии.
- `deploy/` — установка и конфигурация прокси.

Для новой игры создайте модуль с `start(ids)`, `act(state, player_id, action)` и `view(state, player_id)`. Зарегистрируйте его в `ENGINES`, добавьте предел игроков в серверной проверке, карточку в каталоге и экран действий. `view` должен возвращать только публичное и собственное состояние игрока: полное серверное состояние клиенту не передаётся. Новая игра не требует переписывать комнаты или слой хранения.

## Проверки

```bash
python3 -m unittest discover -s tests -v
```

Проверяются распределение ролей, приватность, порядок карт, смерть до хода, реакции, все трикстеры, победы, ограничения правительств, вето, хаос и сохранение комнаты. В набор входят 100 полных автоматических партий Secret Hitler и 80 партий «Ночи ниндзя». См. `TEST_REPORT.md` о фактически выполненных проверках и ограничениях.
